## 四、标注规则

- **状态：当前入口**：后续 Agent 优先阅读，并以其描述为当前维护基线。
- **状态：当前清单/指南**：用于执行开发、测试或安全操作；内容应随实现变化同步更新。
- **状态：历史记录**：保留审查和演进证据，不应单独作为当前代码状态结论。
- **状态：规划基线**：描述目标和方向，不能替代实际代码扫描结果。
- **权威性：高**：用于当前任务、操作或验收；如与历史文档冲突，以代码和最新高权威文档为准。
- **权威性：中**：参考资料、历史记录或存在重叠/原稿性质，需要结合代码核对。

## 五、维护约定

1. 新增项目文档优先放入 `Markdown/Project/`、`Markdown/Development/`、`Markdown/Tests/`、`Markdown/Security/`、`Markdown/Summaries/` 或 `Markdown/CodeReview/`。
2. 新增或删除文档后同步更新本文档的数量、推荐阅读顺序和分类表。
3. 文档中的路径使用相对路径；平台专用命令明确标注 Windows/macOS/Linux。
4. 测试结论必须写明日期、环境和实际命令，不能把规划内容写成已完成事实。
5. API Key、Cookie、Token、凭据文件和真实响应不得写入 Markdown。
6. `../Summaries/README_Project_Status.md` 记录阶段状态，`../Development/CHANGELOG.md` 记录时间线，`优化建议.md` 记录待办，三者职责不要混用。
